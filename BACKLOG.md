# Беклог

## Перевірка на персонах: рейтинг 400 (6 міс) і рейтинг 600 (3 роки)

Прогнав профіль і рушій тактики через дві персони. Знайдені прогалини —
підпункти нижче.

### Чесніше повідомлення Плану А, коли немає справжніх сильних сторін

Перевірено кодом: у гравця-новачка з усіма ударами на 1–2/5 `strongSkills()`
все одно повертає «найменш слабкі» 2 удари (напр., форхенд 2/5), і Плану А
впевнено радить будувати розіграш саме на них. При цьому текст у профілі
стверджує «План А завжди спирається на удари з оцінкою 4–5. Слабші удари не
стануть опорою тактики» — це неправда саме в цьому випадку. Потрібно: або
показувати чесне попередження («поки жодного удару немає на рівні 4+, це
відносно сильніші сторони, а не готова зброя»), або взагалі не будувати План А
з мотивуючих формулювань, поки немає хоча б одного удару 4+.

### Прогрес у часі (історія оцінок, а не лише поточний знімок)

Зараз `p.skills` — це один поточний стан, який перезаписується при кожному
редагуванні профілю. Немає способу побачити, як зросла оцінка форхенду за
6 місяців чи за 3 роки. Зберігати історію оцінок (дата + значення по кожному
удару) і показувати графік/тренд прогресу — важливо для обох персон, але
особливо для новачка на 6 місяців, який хоче бачити рух вперед.

### Місяці замість лише років у «Досвід і рівень»

Поле «Років у тенісі» — ціле число років, тому гравець 6 місяців вписує «0» і
втрачає сенс поля. Додати варіант введення в місяцях для першого року
(напр., перемикач «< 1 року, скільки місяців»).

### «Ще не визначився» у виборі ігрового стилю

У «Про свою гру» 4 стилі (агресивний бомбардир / універсал / контратакувальник
/ ставка на подачу) без нейтральної опції. Новачок на 6 місяців ще не має
сформованого стилю — змушувати обирати один із чотирьох передчасно. Додати
п'яту опцію «Ще не визначився / формується».

### Профіль суперника, що накопичується між зустрічами

Пов'язано з пунктом «Нотатки про суперника» нижче, але для гравця 3+ роки, який
регулярно грає з тими самими людьми в лізі/клубі, нотатки в кожному матчі
ізольовані одна від одної. Потрібна окрема сутність «Суперник» з історією
зустрічей і накопиченими нотатками, а не просто текстове поле в кожному матчі.

### Парна гра

Застосунок повністю розрахований на одиночну гру (рахунок, тактика, форми
матчу/турніру). Гравець 3 роки з рейтингом 600 цілком може грати парну на
своєму клубі/лізі — наразі для цього немає жодних полів і тактики.

### Сезонні цілі / довгострокове планування

Обидві персони зараз бачать лише окремі турніри/матчі/тренування без спільної
мети. Додати можливість поставити ціль (напр., «вийти на NTRP 4.0 до грудня»
або «пік форми до обласного чемпіонату») і бачити прогрес до неї через усі
події — природне продовження пункту «Розширена статистика по турнірах» нижче.

## Онбординг: пояснення призначення кожної сторінки

Реалізувати вступний тур застосунком — коротко пояснити навіщо потрібна кожна
вкладка/сторінка і що на ній робити: Головна, План (План А/Б, розминка,
мікроцілі), SOS (швидка підказка в складний момент матчу), Матчі (запис
результатів і звіт), Профіль (дані, ракетка, удари, самопочуття — навіщо це
запитується і як впливає на поради). Показувати при першому вході після
створення профілю, з можливістю пропустити й переглянути пізніше (напр., кнопка
«?» на кожному екрані).

## ШІ-аналіз гри гравця

Профіль уже збирає ігровий стиль, тенденції (мультивибір) і вільний опис
(«Про свою гру») саме з розрахунком на це. Замінити/доповнити поточну
rule-based логіку (`genPlanA`, `genPlanB`, `genWarmup`, `genHydration`) на
запит до LLM, який враховує весь профіль (удари, стиль, тенденції, самопочуття,
ракетку) і генерує персональніший аналіз і тактику, ніж жорсткі шаблони.
Потребує backend (ключ API не можна тримати в клієнтському коді статичного
сайту) — ймовірно, той самий Supabase (Edge Function) або окремий сервер.

## Нотатки про суперника

У формі матчу (`scrMatchForm`) додати опційне поле «Про суперника»: сильні й
слабкі сторони, стиль гри, відомі звички (напр., «слабкий бекхенд», «часто йде
до сітки»). Використати це в `genPlanA`/`genPlanB` для конкретного матчу —
тактика підлаштовується не лише під гравця, а й під суперника.

## Автопогода замість ручного вводу

У формі турніру (`scrTournForm`) температура і вітер вводяться вручну. Додати
автопідтягування прогнозу за датою і локацією (потрібен геокодинг адреси корту
або ручний вибір міста + погодне API), з можливістю відредагувати вручну, якщо
прогноз неточний.

## Розширена статистика по турнірах

На Головній зараз лише список минулих турнірів з рахунком В–П. Додати окремий
розділ/екран з трендами: % перемог по покриттю корту, по типу суперника (якщо
з’являться нотатки про суперника), середня дотримання Плану А, динаміка за
останні N турнірів. Дані для цього вже збираються (`matches`, `report`) —
потрібна лише агрегація і візуалізація.

## Експорт турніру / матчу / тренування у PDF (та інші формати)

Кнопка «Завантажити PDF» на екранах перегляду турніру (звіт), окремого матчу і
тренування — щоб зручно переслати тренеру для аналізу. Один документ на одну
подію, орієнтація на швидке сканування тренером (заголовок + таблиця ключових
цифр + текстові нотатки), а не суцільний текст. Використати наявний PDF-скіл
для генерації файлу; текстова версія (як зараз через «Поділитися») лишається
як швидка альтернатива без завантаження файлу.

Орієнтовний вміст на кожен тип:

**Турнір** — шапка (назва, дата, покриття/умови); таблиця матчів (суперник,
рахунок, В/П, тривалість); середні показники по турніру (дотримання плану,
енергія, гідратація); ключові висновки (вже генеруються рушієм звіту);
кількість і ефективність підказок у складні моменти.

**Матч** (окремий/спаринг) — суперник і нотатки про його стиль; покриття,
формат, тривалість; рахунок; самопочуття (енергія/гідратація/втома/настрій);
що спрацювало / не спрацювало; один висновок.

**Тренування** — тип (групове/індивідуальне), тренер (якщо є); фокус і
вправи/повторення; тривалість, RPE і навантаження (тривалість × RPE); оцінка
якості; самопочуття після; нотатки й фокус на наступний раз.

Додатково розглянути формати, крім PDF: звичайний текст (уже є через
«Поділитися»/буфer обміну) і, можливо, CSV/XLSX для тих, хто веде власну
таблицю прогресу.

## Хмарна синхронізація + вхід через Google (відкладено)

У `index.html` вже є код для опціональної хмарної синхронізації через Supabase
(вхід через Google, дані профілю/турнірів доступні з будь-якого пристрою).
Зараз він неактивний — увімкнеться сам, як тільки будуть підставлені реальні
`SUPA_URL` і `SUPA_ANON_KEY` (зараз там заглушки `YOUR-PROJECT` / `YOUR-ANON-PUBLIC-KEY`).
До того часу сайт працює як і раніше — лише локальне збереження (localStorage).

Що знадобиться, коли повернемось до цього:

1. Створити проєкт на supabase.com
2. Виконати в SQL Editor:
   ```sql
   create table public.user_data (
     user_id uuid primary key references auth.users(id) on delete cascade,
     data jsonb not null default '{}'::jsonb,
     updated_at timestamptz not null default now()
   );
   alter table public.user_data enable row level security;
   create policy "select own" on public.user_data for select using (auth.uid() = user_id);
   create policy "insert own" on public.user_data for insert with check (auth.uid() = user_id);
   create policy "update own" on public.user_data for update using (auth.uid() = user_id);
   ```
3. Authentication → Providers → Google → Enable (потрібен OAuth Client ID/Secret
   з Google Cloud Console, redirect URI підкаже сама сторінка Supabase)
4. Authentication → URL Configuration → Site URL і Redirect URLs = адреса деплою
5. Дати Claude значення Project URL і anon public key з Project Settings → API
